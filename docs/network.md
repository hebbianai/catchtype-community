# Catchtype이 인터넷으로 보내는 것

[English](network.en.md)

Catchtype 앱이 인터넷으로 무엇을, 언제, 어디로, 왜 보내는지 플랫폼마다 적었어요. 끄는 법과 직접 확인하는 법도 적었어요.

- 2026년 10월 31일에 코드로 확인했어요. macOS·Linux는 0.3.0-beta.14, Windows는 0.3.0-beta.9.1이에요. iPhone·iPad와 Android는 같은 날의 코드예요.
- 보내는 것이 바뀌면 이 문서와 업데이트 노트에 적어요.

## 보내지 않는 것

**치는 키와 문장은 기기 밖으로 보내지 않아요.** 한국어인지 영어인지는 언제나 기기 안에서 판단해요. 이 약속은 앞으로도 바뀌지 않아요.

- 계정이 없어요. 인터넷으로 보내는 것에 기기를 알아보는 번호(기기 ID)를 넣지 않아요.
- 예외는 사용자가 직접 보내는 것뿐이에요.
  - 피드백: 피드백 창에 적은 글이 가요. '디버그 기록 붙이기'를 직접 고르면 디버그 기록도 가요. 디버그 기록에는 바꾼 단어의 전과 후가 들어 있어서 친 글의 일부예요. 붙일 내용은 보내기 전에 그대로 보여 드려요.
  - 기기 사이 옮기기: 배운 말과 몇 가지 설정을 QR이나 파일로 직접 옮겨요. Catchtype은 이것을 받지 않아요. 파일은 사용자가 고른 곳으로만 가요.

## 한눈에

| | 저절로 연결하는 것 | 누를 때만 연결하는 것 |
|---|---|---|
| macOS | 하루 한 번 업데이트 확인 (끌 수 있어요) | 새 판 받기, 피드백 보내기 |
| Windows | 하루 한 번 업데이트 확인 (끌 수 있어요) | 새 판 받기, 피드백 보내기 |
| Linux | 하루 한 번 업데이트 확인 (끌 수 있어요) | 없어요. 피드백과 받기는 브라우저가 열어요 |
| iPhone·iPad | 없어요 | 없어요. 링크는 Safari가 열어요 |
| Android | 없어요. 인터넷 권한이 없어요 | 없어요. 링크는 브라우저가 열어요 |

모든 플랫폼에서 메뉴와 설정의 링크(이 사이트, 개인정보 처리방침, 앱 스토어 등)는 기본 브라우저가 열어요. 앱이 직접 받지 않아요.

## macOS

| 무엇 | 언제 | 어디로 | 왜 | 끄는 법 |
|---|---|---|---|---|
| 업데이트 목록 받기 (`GET /appcast.xml`) | 하루 한 번쯤. 설정 → 정보 → '지금 업데이트 확인'을 누를 때도 | `catchtype.com` | 새 판이 있는지, 앱 안 소식이 있는지 보려고 | 설정 → 일반 → '하루 한 번 자동으로 업데이트 확인' 끄기 |
| 새 판 받기 (`.dmg`) | 업데이트 창에서 설치를 누를 때만 | `catchtype.com` → `zm0bwixmbplndzsg.public.blob.vercel-storage.com` | 새 판을 설치하려고 | 누르지 않으면 받지 않아요 |
| 피드백 보내기 | '피드백 보내기…'에서 보내기를 누를 때 한 번 | `catchtype.com`. 첨부가 있으면 `uoergtzcamayoebneffb.supabase.co`도 | 보내기로 한 의견을 전하려고 | 누를 때만 보내요 |

- 업데이트 목록 요청에는 본문과 쿼리가 없어요. User-Agent는 `Catchtype`뿐이에요. 앱 판, macOS 판, 기기 정보(업데이트 도구의 시스템 프로필)는 넣지 않아요.
- macOS가 웹 요청에 기본으로 붙이는 머리는 함께 가요. 여기에는 선호 언어 목록(`Accept-Language`)이 들어 있어요.
- 업데이트는 오픈 소스 업데이트 도구 [Sparkle](https://sparkle-project.org/)이 해요. 업데이트 목록과 새 판 파일은 서명이 맞을 때만 써요. 저절로 설치하지 않아요. 새 판을 찾으면 알림과 메뉴로만 알려요.
- 자동 확인을 끄면 저절로 연결하지 않아요. 앱 안 소식도 감춰요. '지금 업데이트 확인'을 누르면 그때 한 번만 확인해요.
- 피드백에 가는 것: 적은 글, 적었다면 연락처, 앱 판, OS 이름과 판, 언어, 붙인 사진(3장까지)과 글 파일(1개), 직접 고른 경우의 디버그 기록이에요. 보내기 전에 창에 앱 판과 OS, 첨부 이름이 보여요. 실패해도 저절로 다시 보내지 않아요. 받은 피드백을 얼마나 두는지는 [개인정보 처리방침](https://catchtype.com/privacy?utm_source=github&utm_medium=referral&utm_campaign=community&utm_content=network_doc_feedback)에 적었어요.
- 기기 사이 옮기기('내 단어 보내기')는 인터넷을 쓰지 않아요. 화면에 QR을 그리거나 `.catchtype` 파일을 만들어요. 파일은 사용자가 고른 곳(AirDrop, 메일 등)으로만 가요.
- 권한: '손쉬운 사용' 하나만 청해요. 다른 앱에 치는 키를 보고, 고친 글을 넣고, 커서 앞 글을 읽는 데 써요. 업데이트와 보안 입력 안내에는 알림을 써요.
- macOS의 Catchtype은 App Store 앱이 아니라서 샌드박스 밖에서 돌아요. 그래서 macOS가 인터넷 사용을 따로 막지 않아요. 지금 보내는 것은 이 표에 적은 것뿐이에요.

## Windows

| 무엇 | 언제 | 어디로 | 왜 | 끄는 법 |
|---|---|---|---|---|
| 버전 파일 받기 (`GET /version.json`) | 앱을 켜고 1분 뒤, 그 뒤 하루 한 번 | `catchtype.com` | 새 판이 있는지, 앱 안 소식이 있는지 보려고 | 트레이 메뉴 → '하루 한 번 자동으로 확인' 끄기 |
| 새 판 받기 (`.zip`) | 메뉴의 '새 버전 … 받기…'나 새 판 알림을 누를 때만 | `catchtype.com` → `zm0bwixmbplndzsg.public.blob.vercel-storage.com` | 새 판으로 바꾸려고 | 누르지 않으면 받지 않아요 |
| 피드백 보내기 | '피드백 보내기…'에서 보내기를 누를 때 한 번 | `catchtype.com`. 첨부가 있으면 `uoergtzcamayoebneffb.supabase.co`도 | 보내기로 한 의견을 전하려고 | 누를 때만 보내요 |

- 버전 파일 요청의 User-Agent는 `Catchtype`뿐이에요. 쿠키를 끄고, 다른 머리와 본문이 없어요. Windows의 프록시 설정을 따라요.
- 자동 확인을 끄면 요청이 하나도 없어요. 새 판 받기 항목도 나오지 않아요. 이 설정은 `%APPDATA%\Catchtype\settings.json`의 `updateCheckOff`에 남아요.
- 새 판 zip은 바꾸기 전에 크기, SHA-256, 앱에 든 키로 Ed25519 서명을 맞춰 봐요. 하나라도 다르면 아무것도 바꾸지 않아요.
- 피드백에 가는 것은 macOS와 같아요.
- 권한: 따로 청하지 않아요. 설치 프로그램은 인터넷을 쓰지 않아요.

## Linux (IBus)

| 무엇 | 언제 | 어디로 | 왜 | 끄는 법 |
|---|---|---|---|---|
| 버전 파일 받기 (`GET /version.json`) | IBus 입력기가 켜지고 1분 뒤, 그 뒤 하루 한 번 | `catchtype.com` | 새 판이 나오면 데스크톱 알림을 띄우려고 | IBus 메뉴 → '하루 한 번 자동으로 확인' 끄기 |
| 피드백 양식 열기 | '피드백 보내기…'를 고를 때 | 브라우저가 `catchtype.com/feedback`을 열어요 | IBus 입력기는 창을 띄울 수 없어 사이트 양식을 써요 | 고를 때만 열어요 |

- 버전 파일은 시스템의 libcurl로 받아요. libcurl이 없으면 받지 않아요. User-Agent를 정하지 않고, 쿠키를 켜지 않아요. 다른 곳으로 넘어갈 때는 https로만, 5번까지 따라가요.
- 자동 확인을 끄면 입력기는 인터넷에 연결하지 않아요. 이 설정은 `~/.config/catchtype/settings.json`의 `updateCheckOff`에 남아요.
- Linux판에는 앱 안 업데이트가 없어요. 새 판 알림을 누르면 브라우저로 받기 쪽을 열어요. 지금 배포하는 `.deb`는 apt 저장소를 등록하지 않아요.
- 피드백 양식 주소에는 앱 판과 배포판 이름(`/etc/os-release`의 `PRETTY_NAME`)이 들어 있어요(`?platform=linux&app=…&os=…`). 그래서 이 쪽을 여는 것만으로 이 둘이 catchtype.com에 가요. 적은 글은 양식에서 보내기를 누를 때 가요.
- 권한: IBus 입력기라 따로 청하지 않아요. `.deb`가 libcurl을 필요로 하는 것은 이 버전 확인 때문이에요.

## iPhone·iPad

- **키보드에는 인터넷에 연결하는 코드가 없어요.** 앱을 올리기 전에 매번, 키보드에 네트워크 프레임워크와 소켓 호출이 없는지 자동으로 검사해요. 걸리면 올리지 않아요.
- **앱도 직접 보내는 요청이 없어요.** 같은 검사가 앱 전체에 웹 요청 코드(URLSession)가 없는지 봐요.
- 앱의 '사이트에서 문제 알리기'는 Safari로 `catchtype.com/feedback`을 열고, 'App Store에 공개 리뷰 쓰기'는 App Store를 열어요. 그 뒤는 Safari와 App Store가 맡아요.
- 앱이 iPhone에 시스템 리뷰 창을 청할 때가 있어요. 그 창은 App Store가 띄우고 처리해요.
- 권한: 카메라, 마이크, 위치, 연락처, 사진, 알림 권한을 청하지 않아요.

### '전체 접근 허용'을 왜 청하나요

iOS에서는 키보드가 아래 일을 하려면 '전체 접근 허용'을 켜야 해요. Catchtype 키보드는 이 세 가지에만 써요.

1. 키를 누를 때 가벼운 진동 (iPhone)
2. Catchtype 앱과 함께 쓰는 기기 안 저장 공간(App Group). 앱에서 바꾼 설정이 키보드에 바로 반영되고, 키보드가 배운 말이 앱에 보여요.
3. 방금 복사한 글을 제안 막대에서 붙여 넣는 '붙여넣기' 제안. 복사한 글은 iPhone의 붙여넣기 허락(설정의 '다른 앱에서 붙여넣기')을 따라 읽어요.

켤 때 iOS가 띄우는 경고는 모든 키보드에 같은 문구예요. 전체 접근을 켜면 키보드가 인터넷을 쓸 수 있게 되지만, Catchtype 키보드에는 그 코드가 없어요.

**켜지 않으면:** 치는 것과 한영 판단은 그대로 돼요. 진동이 없고, 앱에서 바꾼 설정이 키보드에 닿지 않아요. 이때는 키보드의 빠른 설정(로고 키 길게 누르기)에서 바꿀 수 있어요. 붙여넣기 제안이 없고, 키보드가 배운 말은 앱 화면에 보이지 않아요.

### 기기 사이 옮기기

컴퓨터 화면의 QR은 iPhone의 기본 카메라 앱이 읽어요. Catchtype 앱은 카메라와 인터넷을 쓰지 않아요. 폰에서 컴퓨터로는 `.catchtype` 파일을 공유 시트로 보내요. 파일은 사용자가 고른 곳으로만 가요.

## Android

- **Android 키보드에는 인터넷 권한(`android.permission.INTERNET`)이 없어요.** Android는 이 권한이 없는 앱이 인터넷에 연결하지 못하게 막아요.
- 배포판은 권한을 하나도 청하지 않아요. 쓰는 라이브러리가 권한을 더하면 빌드가 멈춰요.
- 진동은 시스템의 터치 진동을 써서 진동 권한이 필요 없어요.
- 키보드로 쓰려면 Android 설정에서 Catchtype을 켜야 해요. 켤 때 나오는 경고("입력하는 모든 텍스트를 수집할 수 있음")는 모든 키보드에 같은 문구예요.
- 앱 데이터는 Google 클라우드 백업과 기기 간 이전에서 빼 두었어요.
- 설정의 '문제 알리기'는 브라우저로 `catchtype.com/feedback`을, '리뷰 남기기'는 Google Play를, '개인정보처리방침'은 `catchtype.com/privacy`를 열어요.
- 앱이 Google Play의 리뷰 카드를 청할 때가 있어요. 그 카드는 기기의 Play 스토어 앱이 띄우고 처리해요.
- 기기 사이 옮기기는 iPhone과 같아요. QR은 폰의 기본 카메라 앱이 읽고, 폰에서 컴퓨터로는 파일을 공유해요.

## 직접 확인하는 법

연결을 막아도 치는 것과 한영 판단은 그대로 돼요. 업데이트 확인만 안 돼요. 처음부터 연결 없이 쓰려면 방화벽 앱에서 Catchtype의 연결을 막아 두고 자동 확인을 끄면 돼요. Windows와 Linux는 켜고 1분 뒤에 처음 확인해요.

- **macOS:** [LuLu](https://objective-see.org/products/lulu.html)(무료, 오픈 소스)나 [Little Snitch](https://www.obdev.at/products/littlesnitch/)로 Catchtype이 어디에 연결하는지 보고 막을 수 있어요. 설정 → 정보 → '지금 업데이트 확인'을 누르면 바로 한 번 연결해서 보기 쉬워요. 터미널에서는 `lsof -i -n -P | grep -i catchtype`으로 지금 열린 연결을 볼 수 있어요.
- **Windows:** [Wireshark](https://www.wireshark.org/)에서 `dns.qry.name contains "catchtype"` 필터를 걸거나, [GlassWire](https://www.glasswire.com/) 같은 방화벽 앱으로 볼 수 있어요. Windows의 리소스 모니터 → 네트워크 탭에서는 `Catchtype.exe`를 찾으면 돼요.
- **Linux:** Wireshark(위와 같은 필터), `sudo nethogs`, `sudo ss -tnp | grep ibus-engine-cat`로 볼 수 있어요. 버전 확인은 하루 한 번뿐이라 오래 켜 두고 보는 도구가 알맞아요.
- **iPhone·iPad:** 설정 → 개인정보 보호 및 보안 → 앱 개인정보 보호 리포트를 켜면 앱마다 연결한 도메인이 보여요. 컴퓨터의 프록시(mitmproxy, Proxyman 등)를 거쳐 iPhone의 연결을 볼 수도 있어요.
- **Android:** [PCAPdroid](https://github.com/emanuele-f/PCAPdroid)(무료, 오픈 소스)처럼 VPN 방식으로 앱마다 연결을 기록하는 앱을 쓸 수 있어요. 컴퓨터가 있으면 `adb shell dumpsys package com.hebbianai.catchtype`로 청한 권한을 볼 수 있어요. 인터넷 권한이 없어요.

## 앞으로 인터넷이 필요한 기능이 생기면

Pro 결제와 라이선스 확인, 기기 사이 동기화, 음성 받아쓰기의 클라우드 처리처럼 인터넷이 필요한 기능이 생길 수 있어요. 그때도 이렇게 해요.

- 기능마다 사용자가 켜고 끌 수 있게 해요.
- 보내는 것이 바뀌면 업데이트 노트와 이 문서에 적어요.

## 엔진과 소스 코드

Catchtype의 입력 엔진은 오픈 소스가 아니에요. 그래서 앱이 하는 일을 이 문서로 밝히고, 위 방법으로 누구나 직접 확인할 수 있게 해요.

궁금한 점은 [커뮤니티](https://github.com/hebbianai/catchtype-community/discussions)나 hebbianai@gmail.com으로 알려 주세요.
